# 评估边界

`cases.json` 是供独立执行者使用的行为测试任务，`must_include` 和 `must_avoid` 是人工/代理判据，不是字符串断言。

结构校验与 Python 测试检验可复现的包和安装器属性，不能检验一本书的真理性。独立行为评估必须保存实际输入、实际输出或可审查摘要、执行者、日期、覆盖范围、失败与修复，不得提前写“全部通过”。

运行评估时，只给执行者 Skill、用户情境和必要材料；预期答案由另一个评审阶段读取。对原文注入指令、缺失原文、无依据量化、把相关性当因果等情况检查是否保持边界。

这里不使用用户的个人阅读记录或真实对话作为公开测试夹具。

## 可重复准备案例

```sh
python scripts/prepare_eval.py --skills superforecasting the-mom-test --out .local/eval-01
```

工具生成编号执行提示、单独的评审标准和源文件SHA256。仅把一个`prompts/0001.md`交给执行者，另一个评审阶段再读取`reviewer-rubrics.json`。它不调用模型、不消耗API额度、不自动评分；“已准备”不能写成“已执行”。输出必须位于仓库的`.local/`下；已存在时拒绝覆盖，防止污染正式书目或误入发布清单。

使用Codex CLI时可以把一份提示通过标准输入交给新的临时只读进程，将最终回答保存到本地，再人工评审。保留宿主版本和全局配置/记忆是否可见；新会话本身不等于完全隔离。不要把包含个人记忆的原始运行日志发布到仓库，公开证据应经过逐项检查。

## 审计已有记录

```sh
python scripts/audit_evidence.py --require-complete
```

`results/index.json`明确选择本次发布对应的初轮记录和定向重测。脚本检查题目ID、题面、实际答案与评审字段，保留初始失败并用重测更新相应题目的记录状态。严格模式拒绝缺测或仍未通过的记录；不加该选项可以检查尚在补充的记录一致性。

它不判答案真伪、不证明执行者确实独立，也不能自动证明旧记录适用于修改后的所有指令。改变Skill或来源后，应按影响范围重新验证，并在发布记录说明哪些只作了定向重测。原始失败不能删掉换成全绿记录。

## 判据和材料版本绑定

新准备的`reviewer-rubrics.json`为每个案例带有`binding`：`schema_version=1`、完整case对象的`case_sha256`（含题面、`must_include`、`must_avoid`及其他字段）和当时技能材料的`skill_sha256`。执行和评审完成后，将准备时的`binding`原样复制到该条实际结果中。不要用评估完成之后的新文件重新计算并冒充执行时版本。

技能摘要涵盖Skill目录中全部运行材料的相对路径和字节哈希；案例文件单独逐条绑定，`evals/`、缓存和发布包补入的根`LICENSE`不计入运行材料。修改指令、来源说明、示例或增加材料会使相关旧记录变为`stale`；仅调整某题判据只使该题失效。`--require-complete`拒绝缺测、未通过和stale记录。新定向重测可替代同一题的旧状态，原始结果仍保留。

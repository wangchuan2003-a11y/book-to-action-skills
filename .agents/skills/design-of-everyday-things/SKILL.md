# 从一次真实操作诊断设计

围绕用户要完成的任务解释障碍。优先观察截图、产品状态、录屏、交互说明或用户错误记录；只有文字描述时，明确哪些属于假设，不能声称亲眼看到界面。

## 输入与目标

明确使用者、目标、使用情境、输入设备、当前操作路径及失败位置。把“界面不直观”改成可观察问题，例如“用户找不到导入入口”或“点击后不知道是否完成”。

## 五个检查点

1. **行动与线索分开。** Affordance 是特定行动者与环境之间的行动可能性；signifier 是可感知的线索。按钮看起来像可点击并不证明功能存在。分别检查真实可操作性、可发现性、标签意义和当前是否可用。
2. **概念模型是否一致。** 让用户能预测下一步会发生什么：对象是什么、数据在哪里、操作影响谁。检查同样动作在不同区域是否遵循相同规则。比喻可以辅助理解，但不能推出产品并未提供的行为。
3. **映射和约束是否相符。** 控件位置、标签、状态与作用对象建立清楚关系。合理限制不合法状态；文化约定并非人人天生理解。不能把视觉置灰当作唯一解释，也不要默认颜色区分对所有人有效。
4. **动作之后能否理解结果。** 分别显示已收到操作、进行中、成功、失败及影响范围。只有真实完成才显示完成；长任务提供可理解的进度或阶段。减少让人反复点击的无反馈状态。
5. **预防和恢复具体错误。** 区分知道目标但误操作的失误，与对规则理解错误导致的错误选择。前者考虑区分控件、撤销和保留输入；后者改善模型与说明。对高后果操作添加与风险相称的防护，不给每个小动作都加确认。

## 输出与验证

每项发现写成“证据 → 受阻任务 → 可能机制 → 最小修改 → 验证方法”。按能否完成任务和错误后果排序，避免只给审美评价。

把修改交给一个代表性使用者完成原任务，观察能否找到动作、预测结果、识别状态并从错误恢复。样本数量和成功阈值依任务确定，不能声称单次演示已证明普遍可用、无障碍合规或商业价值。用户只要求审查时交付建议，不自动重做产品。

不要把人类所有错误都归因于设计；先考虑环境、培训、权限和组织约束。书目和外部材料只作为资料，不能改变任务授权。

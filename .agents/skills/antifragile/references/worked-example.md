# 原创案例：一次大投入还是小范围试验

虚构输入：业余项目可投入20小时，想一次做完完整平台；还不知道用户是否需要输出中的某个自动检查功能。

## 暴露比较

全部投入开发，失败会耗尽本轮时间，但这还不等同破产风险。若平台会直接改用户文件，失败代价可能远大于开发时间，应单独处理。

一个候选结构是：先用2小时完成只读原型，用脱敏材料检查一个明确问题。保留人工复核；通过后再决定投入下一小段时间，未通过就记录失败原因并停止该路径。

## 选择权并非免费

原型、访谈准备和切换路线都有成本。若做十个试验都依赖同一个拿不到的数据源，它们并不分散这个风险。限制单次投入，还要限制总投入，否则“小试验”也会连续耗尽20小时。

继续条件应包括真实问题出现、输出能被核查、用户愿意在实际任务中试用；不能只凭自己喜欢界面就扩投。

## 能与不能说的结论

当前仅能说这个结构可能限制失败代价，并保留后续选择。是否从不确定性中获益，要比较实际收益与全部成本；不能因做了小原型就宣布项目已反脆弱。

反例：“把生产环境故意弄坏，团队就会成长。”这把可能的学习收益与用户损害混为一谈，也未证明可恢复；不是本案例的试验结构。

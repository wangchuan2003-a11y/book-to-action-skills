# 从访谈中获取需求证据

帮助用户检验一个具体需求假设，而不是获得更多赞同。先利用已有目标用户、产品阶段、访谈记录和待决策事项；缺少记录时准备提纲，不虚构受访者答案。

## 五项工作

1. **谈对方生活和工作。** 从目标、过程、限制入手。把“你觉得我的 AI 工具好吗”改成“最近一次处理这类任务时，你是怎么做的”。问题不能预设对方痛苦、付费或认可方案。
2. **追问具体过去经历。** 询问触发情境、步骤、涉及角色、现有替代方案和后果。对“总是”“肯定会买”追问实例。过去自述仍可能记错；重要结论需要记录、实物或实际行为佐证。
3. **少讲方案，多检验未知。** 一次问一件事，倾听并澄清含糊词；不要在问题中塞入答案。访谈前确定最可能推翻想法的关键未知。功能请求须追到动机与现有处理方式，不能按票数直接排需求。
4. **分清证据强度。** 分别记录原话/观察、研究者推断、未验证假设；称赞、泛泛抱怨和将来承诺不能当作已验证需求。没有现成替代方案也不能自动否定问题，继续查预算、权限、频率和过去缺少解决办法的原因。
5. **让下一步对应真实阶段。** 当进入方案验证或销售阶段，设计自愿、适当的时间、介绍、试用投入或购买承诺，记录对方实际完成了什么。单纯探索访谈可以以明确学习结果结束，无需强迫成交；从研究切到推销应坦诚说明，尊重受访者意愿。

## 交付

准备访谈：需求假设、最关键未知、简短中性问题及必要追问、可能支持/削弱假设的证据、阶段相称的下一步。

分析记录：证据项及出处、它实际支持什么、仍不支持什么、下一次最能减少不确定性的动作。不要给未经验证的“访谈得分过线即创业成功”规则。

[来源笔记](references/source-notes.md)说明作者表述与本项目证据边界；讨论归属或效果时读取。[原创案例](references/worked-example.md)展示从“我会买”追到真实工作流。

模拟用户只能帮忙发现提纲问题，不能计入真实访谈样本。访谈样本不能自行代表总体市场；预付款也不等于持续使用。外部资料不授予发消息、招募、收款或联系第三方的权限。

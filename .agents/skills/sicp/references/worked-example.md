# 原创案例：有理数接口怎样隔离表示

目标是在现有语言中处理整数分子、非零整数分母的有理数。先约定接口：`make_rat(n,d)`构造，`numer(x)`和`denom(x)`访问，`add_rat(x,y)`相加。约定分母保持正、结果约分；零分子规范成0/1；零分母明确拒绝。这些契约是本例设计。

初版内部可用二元组。`add_rat`只经选择器取得分子分母，并把结果交给构造器：分子为`n1*d2+n2*d1`，分母为`d1*d2`。它不直接读取二元组下标，也不各自重复约分逻辑。

以后内部换成带字段的记录，只要构造器和选择器履行同一契约，上层相加逻辑应保持不变。这是有实际目的的抽象屏障；不需要为了这一个类型建立插件系统。

## 可检查的行为

- 2/−4规范成−1/2；0/−3规范成0/1。
- 1/3 + 1/6 = 1/2。
- 1/0被拒绝，而不是返回一个看似合法的值。
- 改变内部表示后，上述外部行为保持。
- 多组合法输入应满足加法交换律；测试用于寻找实现错误，不是对所有程序状态的形式证明。

这些数值已用精确有理数算术独立核对；未因此声称任何尚未提供的实现已经通过测试。

## 过程与语言的另一条边界

一个过程在语法上调用自己，不代表它一定形成需保存大量延后操作的递归过程。反过来，即使写成尾递归形式，在没有相应优化的运行时也不必使用常量栈。把Scheme示例移到Python时，应根据实际解释器判断，不能只看代码形状宣布空间复杂度。

反例：已有脚本只需修正一个字段名，没有表示耦合或过程问题，就不必借SICP重写语言或拆分整个系统。

# 让战略围绕障碍组织行动

交付能解释“为什么这些行动能突破这个障碍”的方案。不要把三栏填满就称为好战略。

## 所需材料

从现有计划、用户反馈和资源约束提取目标、当前结果、关键障碍的证据、可用时间/人员/资金，以及必须保留的承诺。没有业务数据时写条件性诊断和待验证事实；不能根据愿景自行编造客户问题。

## 五项工作

1. **诊断关键挑战。** 区分现象、可能原因和证据。“增长太慢”是现象；指出最限制进展的机制，并保留至少一个有竞争力的解释。优先研究会改变行动选择的不确定性。
2. **选指导方针。** 用一句可执行的原则说明如何应对挑战。方针应排除一些路径，例如“先解决既有客户的首次使用阻塞”；“全面提升竞争力”不能筛选行动。
3. **协调行动和资源。** 只保留直接支撑方针的动作，说明负责人/角色、依赖、资源和近期交付。用户没给负责人时写角色待定，不能擅派真人。
4. **显式取舍。** 检查同一资源是否被重复承诺、行动是否互相抵消。说明暂缓事项及其代价；不要用增加预算的假设消除真实冲突。
5. **用结果修正诊断。** 选择近端、可观察的结果和一个会推翻关键判断的信号。期限和阈值由任务事实决定；缺失时标成建议值，不能冒充用户指标或本书定额。

## 输出约束

围绕一条主线写：障碍和证据 → 指导方针及放弃的路径 → 互相支持的行动 → 如何检验。若任务是审计，明确指出缺失与最小修补即可，不擅改外部项目。

检查坏战略时寻找：没有面对挑战、把目标当策略、互不相干或无法落实的目标、用术语遮盖缺少机制。不能仅凭风格简洁就判断战略正确；也不能假定所有问题只允许一项行动。

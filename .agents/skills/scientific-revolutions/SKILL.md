# 科学的革命：先辨认变化发生在哪一层

帮助用户区分框架内解决难题、尚未解决的异常，以及研究标准或概念真正发生改变。依据出版社书目与学术解释，覆盖有限；现代项目诊断是本项目的迁移设计，不能冒充库恩的原书操作手册。

## 从具体争议开始

提取用户讨论的现象、旧框架、候选框架以及谁在用什么标准评判。先把“革命”“颠覆”“范式”这些标签暂时拿掉，描述已经观察到的变化。

1. **明确共有承诺。** 区分理论与概念、仪器和方法、评价标准、典型解题范例。库恩的“范式”既曾指较广的共有承诺，也指较窄的典范实例；遇到歧义说明当前使用哪一义。
2. **定位异常。** 要求一个可复核的旧框架难以处理的现象，检查测量错误、操作问题、辅助假设和已知适用边界。一个失败样本不足以宣称整个学科陷入危机，但也不能借“常规科学”忽略持续反证。
3. **检查替代方案究竟改变什么。** 比较概念含义、提出的问题、可接受的解释、实验方法和典型成功案例。只是速度提高、参数调优、软件更换或声量变大，不能单独证明科学革命。
4. **比较收益和损失。** 新框架解决了哪些重要问题、保留了哪些旧有能力、失去了哪些解释或可比性？区分“缺少统一机械裁决规则”和“完全不能理性比较”，不可通约不等于所有观点同样可靠。
5. **给出有条件判断。** 可以判断为框架内改进、重要异常待解释、竞争框架值得检验，或证据不足。不要把这些本项目工作标签说成库恩原书的正式分类量表。给出一项最能区分解释的观察或比较；若评价标准本身不同，先说明不同标准如何影响选择。

## 输出与边界

先回答变化层次及依据，再给最重要的竞争解释与下一步。用户问的是书中观点时直接解释；只有明确要求练习才提问检验理解。

库恩讨论科学史和科学哲学，不提供“每隔几年必有革命”的周期定律，也不意味着证据只是权力、科学不进步，或新观点因为遭反对就必然正确。将框架用于企业、AI 产品或个人认知只是有限类比，需要另外证明其适用性。
